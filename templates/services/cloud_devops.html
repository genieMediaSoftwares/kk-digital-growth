Cloud & DevOps: Deployment and CI/CD for the Software We Build

When we build or take over software, we also set up where and how it runs: the cloud platform or servers, the deployment pipeline, a staging environment and the services the application relies on. This work is part of the software project; it is not a separate hosting service.

Discuss your project See how we deliver
What's Included

Three Parts of Getting Software Live

Set up during the project and documented at handover.

Cloud Deployment

Putting the application on the platform that suits its data, budget and control requirements.

  • AWS, Azure, Google Cloud or DigitalOcean
  • A Linux VPS, or servers you already run on-premise
  • Docker containers, with Nginx and Gunicorn where suitable
  • Domain and SSL certificate setup

DevOps & CI/CD

A repeatable way to test and release changes, so releases don't depend on one person's laptop.

  • Git version control on GitHub
  • Automated build and deployment pipelines
  • A staging environment for reviewing changes before release
  • TestFlight and Google Play internal testing for mobile apps

Cloud Configuration & Integrations

Setting up the cloud services an application depends on, where the project needs them.

  • Storage for uploaded documents and images
  • Email delivery for system notifications
  • Push notifications through Firebase
  • Environment settings and secrets kept out of the code

Scope: cloud and DevOps work is delivered as part of software projects we build or take over. We don't offer standalone hosting, hosting plans or uptime SLAs.

Fit

Who It's For and What It Solves

Who Usually Needs This

  • Businesses commissioning new software that want it launched properly, not just handed over as code.
  • Teams taking over an application whose deployment was never documented.
  • Organisations with data-control requirements that need software on their own servers.

Problems It Addresses

  • Releases done by hand, with steps only one person knows.
  • Changes tested directly on the live site because there is no staging copy.
  • Uncertainty about where the application runs and who has access.
  • Missing or expired SSL certificates.
Scope

What's Included, and What Isn't

Included in the Project

  • Choosing the deployment target with you.
  • Setting up staging and production environments.
  • The build and deployment pipeline.
  • Domain, SSL and the cloud services the application needs.
  • Deployment documentation at handover.

Not Included

  • Standalone hosting or managed hosting plans.
  • Uptime guarantees or service level agreements (SLAs).
  • Cloud work unconnected to software we are building or taking over.
  • Cloud provider charges, which are separate from development costs.
Delivery

How Deployment Fits Into a Project

These steps run alongside development, as part of our wider delivery process.

01

Choose the Environment

We agree where the software will run, based on your data, budget and any existing infrastructure.

02

Configure & Containerise

Servers or cloud services are set up, and the application is packaged so it runs the same everywhere.

03

Pipeline & Staging

Automated deployments go to a staging copy first, where you review changes before release.

04

Launch & Hand Over

Production release with domain and SSL in place, followed by deployment documentation.

What We Need to Plan Deployment

  • Any cloud account, servers or hosting you already use.
  • Roughly how many people will use the software.
  • Whether any data must stay on your own servers.
  • Who owns the domain, and access to its DNS settings.
  • For an existing application: its code repository and current setup.

Frequently Asked Questions

Questions About Cloud & DevOps

Do you offer hosting plans?

No. We set up and document the environment for the software we build, on a cloud platform or servers agreed for the project. We don't sell standalone hosting or uptime SLAs.

Can the software run on our own servers?

Yes. Packaging the application in Docker containers lets it run on a private cloud account or on servers inside your own network, if your data needs to stay there.

Which cloud provider should we use?

It depends on your existing accounts, budget and where your data needs to be. We'll recommend an option during the project and explain the trade-offs.

Building Software That Needs to Go Live?

Tell us about the project and any infrastructure you already have. Deployment is planned in from the start.
